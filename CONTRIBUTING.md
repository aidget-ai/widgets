# Contributing a widget

1. Copy `packages/welcome` to `packages/<id>`, choose a unique lowercase ID and name the npm package `@aidget-community/<id>`.
2. Supply a title, description, author, supported platforms, initial size, at least one PNG/JPEG/WebP screenshot and all runtime files. LOGO is optional. Screenshots must show the actual widget.
3. Declare only needed permissions (`script`, `location`, `storage`) and exact HTTPS origins in `network`. No origin wildcards, HTTP, lifecycle scripts or runtime dependency installation is supported. Keep user settings and secrets out of the package. Runtime references must be relative: put scripts, images and fonts under `assets/`, with the main stylesheet at `style.css`. CI parses HTML and CSS to reject missing files, undeclared external origins and unsupported nested frames.
4. Run `npm ci --ignore-scripts`, `npm run registry`, `npm run check`, `npm test` and open a PR. Include a rendering screenshot and platform verification record.
5. A reviewer checks behavior, resources, permissions and screenshots before merge. Anonymous submissions will use the same reviewed PR pipeline when the submission service is available.

Any change to distributed files, including screenshots, requires a new version. A version already in npm or dist is never replaced. Delete a package from main to delist it; historical dist artifacts remain immutable.

Schemas are generated by `cargo run --bin widget-contract` in the aidget repository and copied into this repository. The frontend consumes types generated from the same Rust definitions.
